Sesión 3 - análisis Financiero con LLMs Locales, Crew Multi-Agente & RAG (3.1 + 3.2 + 3.4)

En esta Sesión evolucionamos desde un agente SDR a un ecosistema financiero avanzado con:

  • Un crew de agentes especializados (Researcher, Analyst, Writer, Judge)
  • APIs Numéricas serias (Alpha Vantage, FMP, Finnhub)
  • RAG volátil + Scraping para análisis profundo
  • Integración con el chat UI existente

Flujo General

Usuario -> /stocks o /stocks-rag -> Crew Engine ->
    Researcher -> Analyst -> Writer -> Judge -> Informe final

¿Qué cambia en 3.2?

  • Se mantiene la capa Numérica (Alpha, FMP).
  • Se añade Finnhub básico (earnings próximos, noticias claves).
  • Se introduce un RAG volátil enriquecido que vive solo en RAM.
  • Se scrapean páginas relevantes y se resumen.

Cómo funciona el RAG volátil

1. Researcher scrapea:
    - Yahoo Finance Profile
    - Yahoo News
    - Investor Relations
2. Se limpia el HTML -> texto
3. Se trocea y se generan embeddings temporales
4. Se seleccionan los fragmentos más relevantes para:
    - Analyst
    - Writer
    - Judge

Comportamiento desde el chat

/stocks-rag AAPL NVDA debug -> análisis profundo con RAG

Objetivo

Dejar de usar RAG volátil y pasar a un RAG serio, persistente, propio de sistemas de análisis financiero reales.

Requerimientos

  • Base de datos local:
    • Postgres + pgvector
    • o ChromaDB local
  • Hashes por documento
  • Detección de duplicados
  • Actualización incremental
Pipeline 3.3:
1. Scraping -> texto 2. Hash SHA256 por documento 3. Si hash existe -> no re-scrapear 4. Embedding -> guardar en vector store 5. Recuperación semántica mucho más precisa

Objetivo

Construir un pipeline profesional que combine:

  • time series forecasting
  • gráficos cuantitativos
  • modelos multimodales
  • informe PDF final

Reemplazo del Analyst

Objetivo alcanzado

  • RAG persistente con Postgres + pgvector.
