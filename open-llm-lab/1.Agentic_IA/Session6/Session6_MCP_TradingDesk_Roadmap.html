1) Objetivos y alcance

Al finalizar, podrás montar y depurar un servidor MCP local que expone herramientas (tools) para operar un “Trading Desk” auditable: obtiene datos desde MetaTrader 5, calcula señales básicas y deja rastro claro del porqué.

Incluye (práctico):
  • UI mínima en navegador (obligatoria): panel simple para probar flujo end‑to‑end.
  • MCP real con SDK (Python): server con Tools / Resources / Prompts.
  • Debug con MCP Inspector para ver cada llamada y respuesta.
  • Fuente de datos real: MT5 conectado a broker (demo).
  • Guías reproducibles en tu estructura: Agentic_AI\.venv y Session6.
No incluye (a propósito):
  • Implementar MCP “a mano” (JSON-RPC/transport). Solo teoría.
  • Volver esto un bot real con dinero real. Aquí es aprendizaje + demo/paper.
  • Pegar código largo dentro del HTML. El HTML guía, el código vive en Session6.
Definición de “éxito” (criterio rápido)
  • Puedes abrir MCP Inspector, conectar tu servidor y ver Tools listadas.
  • Puedes ejecutar un tool de mercado (XAUUSD) y recibir JSON válido.
  • Puedes ejecutar un tool de “evaluación” y recibir decisión + justificación.
  • Tienes logs mínimos para auditoría (inputs, outputs, decisión final).

3) Arquitectura MCP (lo que debes entender)

Tu foco es ver claramente Host/Client/Server y el contrato “herramientas” que conectan el razonamiento con capacidades reales.

Componentes (mental model):
  • MCP Server: expone Tools (acciones), Resources (datos) y Prompts (plantillas).
  • MCP Client/Host: consume esas herramientas (puede ser un IDE, inspector o tu orquestador).
  • Inspector: “laboratorio” para probar tools sin depender de un chat/host externo.
Diseño del ejercicio (Trading Desk):
  • MarketData Toolset: OHLC/quote de XAUUSD desde MT5.
  • Analysis Toolset: indicadores básicos y evaluación de escenario.
  • Risk Toolset: validación coherencia SL/TP y riesgo (paper/demo).
  • Logs: todo trazable para iteración futura.
Decisión de implementación (registrada):
  • El servidor MCP se expone por HTTP en http://localhost:8100.
  • Habrá una UI mínima web (misma app/puerto) para probar “Traer datos / Evaluar / Ver logs”.
  • El MCP Inspector se usa en paralelo para inspección fina de tool calls (payloads/latencia/errores).
Teoría “manual” (solo para criterio, NO se implementa)
MCP puede implementarse “a mano” (transporte + JSON-RPC + manejo de mensajes), pero aquí NO lo hacemos: usamos SDK y herramientas nativas. Esta sección existe solo para que sepas qué hay debajo si un día necesitas un híbrido mínimo.

6) Ejercicio: “Trading Desk” (XAUUSD · H1)

Un solo ejercicio que cubre objetivos MCP: tools, recursos, prompts, debugging, y fuente real de datos (MT5).

Qué hace el Trading Desk (en términos funcionales):
  • MarketData: obtiene barras H1 y/o último precio de XAUUSD desde MT5.
  • Analysis: calcula indicadores básicos (ej. EMA/RSI/ATR) y resume contexto.
  • Decision: devuelve una recomendación (Entrar / Esperar / Invalidar) + justificación.
  • Risk: valida coherencia SL/TP y riesgo máximo (paper primero).
  • Audit: guarda logs estructurados (inputs, outputs, decisión).
Tools esperadas (lista conceptual, no código)
  • md_get_latest(symbol)
  • md_get_ohlc(symbol, timeframe, limit)
  • ta_compute_indicators(symbol, timeframe, limit)
  • desk_evaluate(symbol, timeframe) → decisión + porqué
  • risk_validate(entry, sl, tp, max_risk_pct)
  • (Opcional) paper_place_order(...) y paper_manage_position(...)
La lista final de tools exactas se implementa en el código dentro de Session6 (no se pega aquí).
Plan A / Plan B (fuente de datos)
Plan A (principal): MT5 conectado a broker (demo). Es la ruta “real”.
Plan B (fallback): CSV/local cache para probar MCP si MT5 da problemas. Solo para bootstrap.

8) Observabilidad y logs (auditoría)

Tu requisito: poder revisar qué pasó, por qué se decidió y con qué datos. Aquí se define el estándar.

Logs mínimos por tool:
  • timestamp, tool, args
  • latency_ms, result_summary
  • si error: error_type, error_msg
Logs mínimos por decisión:
  • features clave (multi-TF, indicadores principales)
  • acción elegida (enter/skip/manage)
  • justificación (bullets) + “por qué no”
Qué debes poder contestar solo con logs
  • ¿Qué datos consultó y de qué timeframe?
  • ¿Cuál fue el spread/condición de mercado relevante?
  • ¿Qué regla/criterio disparó la decisión final?
  • ¿Qué alternativa se descartó y por qué?

10) Troubleshooting (sin perder horas)

Si algo falla, aquí está el orden de diagnóstico: puertos → venv → MT5 → inspector → logs.

Puerto ocupado
  • Todo el ejercicio usa 8100.
  • Si falla: revisa qué está usando 8100 y cambia el puerto en config (centralizado).
MT5 no responde
  • ¿MT5 está abierto y logueado?
  • ¿El símbolo existe en tu broker? (a veces es XAUUSDm o GOLD).
  • ¿Tienes historial cargado para H1?
Inspector no ve tools
  • ¿El server está corriendo?
  • En esta sesión el transporte es HTTP: verifica que el server esté escuchando en http://localhost:8100.
  • Revisa logs del server primero.
Errores de entorno (.venv)
  • Asegúrate de activar Agentic_AI\.venv y no otro.
  • Valida python -V y pip show mcp / pip show MetaTrader5.
Regla de diagnóstico (la más eficiente)
1) ¿El server imprime logs al arrancar? → 2) ¿Inspector conecta? → 3) ¿Tool simple responde? → 4) recién ahí evalúas decisiones/estrategia.
