Vista general del pensum local-first

Este pensum toma la arquitectura del curso original de agentes IGENTIQ y la re-implementa con un enfoque LLM local-first, dejando ganchos claros para APIs (OpenAI, Anthropic, Gemini, etc.) cuando decidas utilizarlas.

Objetivo: dominar ingeniería agéntica sin depender de un solo proveedor Motor base: modelos locales (DeepSeek, Qwen, Llama3…) sobre RTX 16 GB Estructura: 6 sesiones troncales + proyectos equivalentes al curso original
Resultados de este pensum
  • Montar tu propio “OpenAI local” con LM Studio + Ollama.
  • Diseñar un runtime de agentes propio (Agent, Tools, Runner, Trace).
  • Usar CrewAI y LangGraph con LLM locales como backend.
  • Construir un Operator-like Assistant local con memoria persistente.
  • Crear un Trading Floor multi-agente usando servicios tipo MCP locales.
  • Dejar preparada la capa de integración para que, si lo decides, puedas usar APIs cloud sin reescribir la arquitectura.
Cómo navegar este HTML
  • Usa el panel lateral para saltar a cada sesión.
  • Marca los checkboxes de las listas de tareas: se guardan en localStorage del navegador.
  • La sección de Comparativa te recuerda en todo momento qué parte del curso original estás cubriendo y cómo se traduce a la ruta local.
  • Este documento es tu pensum maestro; las implementaciones, scripts y prompts vivirán en carpetas de proyecto separadas.
Sugerencia: guarda este HTML en una ruta estable (ej. /IA-local/pensum_igentiq_local.html) y ábrelo siempre desde ahí para mantener consistencia en los estados guardados.

Sesión 1 · Laboratorio Local: tu “OpenAI personal”

Objetivo: dejar instalada y verificada la infraestructura de LLMs locales (LM Studio, Ollama, drivers, Python, uv/Git) y entender cómo orquestar un modelo local básico desde código.

Equivalente a: Fundamentos + entorno del curso original Todo corre en tu RTX local (16 GB VRAM) Salida clave: función call_llm_local() + API mínima
Metas de la sesión
  • Instalar / actualizar drivers, Python, Git, uv (o venv si lo prefieres).
  • Instalar y probar LM Studio como explorador de modelos.
  • Instalar y probar Ollama como servidor LLM local.
  • Descargar al menos un modelo general (Qwen / Llama3) y uno de razonamiento (DeepSeek R1 distill).
  • Crear una función `call_llm_local(model, messages)` en Python y exponerla como endpoint HTTP simple (FastAPI / Flask).

Checklist Sesión 1

Entregables técnicos
  • Archivo config_hardware.md con detalles de tu GPU, VRAM y límites prácticos.
  • Script llm_client_local.py con la función call_llm_local().
  • API mínima (ej. main.py con FastAPI) que expone un endpoint /chat para probar el motor local.
  • Notas HTML/Markdown con problemas encontrados y cómo los resolviste (drivers, permisos, VRAM, etc.).
Esta sesión es tu cimiento. Todo lo demás (CrewAI, LangGraph, AutoGen, Capstone) se apoyará en este motor local.

Sesión 2 · Runtime de Agentes & Tools (OpenAI-style pero local)

Objetivo: implementar tu propio runtime de agentes (Agent, Runner, Trace) y un patrón de herramientas compatible con LLMs locales, preparando ganchos para futuros backends API.

Equivalente a: OpenAI Agents SDK + function calling LLM local como motor principal Proyecto: Agente SDR local (ventas)
Metas de la sesión
  • Definir una clase Agent con:
    • nombre, rol, herramientas, memoria, llm_client
  • Definir una clase AgentRunner (o similar) que ejecute el loop de percepción → pensamiento → acción → reflexión.
  • Definir un esquema simple de tool-calls vía JSON: {"tool": "nombre", "args": {...}}.
  • Implementar un router de herramientas que:
    • parsea el JSON que devuelve el modelo,
    • ejecuta la función Python correspondiente,
    • inyecta la respuesta de vuelta en el contexto del modelo.
  • Introducir asyncio para llamadas concurrentes a LLM y herramientas.
  • Construir un agente SDR local que:
    • lea la web de una empresa (scraping básico o HTML descargado),
    • extraiga su propuesta de valor,
    • redacte un correo personalizado.

Checklist Sesión 2

Entregables técnicos
  • agents/runtime.py: definiciones de Agent, Runner, Trace.
  • agents/tools.py: funciones de negocio (ej. get_company_profile(), generate_email()).
  • agents/sdr_agent.py: script principal del agente SDR local.
  • Docs breves sobre:
    • cómo se define una herramienta,
    • cómo el modelo decide usarla,
    • cómo reemplazar el backend local por OpenAI en el futuro.
Esta sesión fija tu forma mental de “agente + herramientas”; más adelante, CrewAI, LangGraph y AutoGen se apoyarán en estos conceptos.

Sesión 3 · CrewAI con LLM Local: equipos de agentes

Objetivo: dominar el patrón de trabajo en equipo con CrewAI usando modelos locales, replicando los proyectos tipo “Stock Picker” y “Debate” sin depender de GPT-4o.

Equivalente a: Semana CrewAI del curso original Backend: Qwen / DeepSeek vía Ollama / LM Studio Proyecto: Stock Picker local y/o sistema de debate
Metas de la sesión
  • Configurar CrewAI para usar tu cliente LLM local (wrapping de call_llm_local).
  • Definir agentes con roles claros: Investigador, Analista, Redactor, Manager.
  • Construir un Crew que:
    • cargue datos de mercado locales (CSV / API gratuita),
    • analice tendencias básicas,
    • produzca un informe de inversión.
  • Explorar patrones jerárquicos (manager agent) y procesos secuenciales.

Checklist Sesión 3

Entregables técnicos
  • crew/config/agents.yaml y crew/config/tasks.yaml adaptados a tu proyecto.
  • crew/stock_picker.py (o equivalente) con el flujo completo.
  • Dataset de prueba (CSV de precios) para no depender de APIs externas.
  • Pequeño informe comparando desempeño del Crew con un agente único.
Aquí consolidarás tu habilidad para pensar en equipos de agentes, una pieza clave para el Capstone de Trading más adelante.

Sesión 4 · LangGraph Local & Memoria Persistente

Objetivo: aprender a modelar procesos como grafos con estado, usando LangGraph sobre un backend LLM local y almacenamiento (SQLite/Postgres) en tu máquina.

Equivalente a: Semana LangGraph + LangSmith Estado y memoria 100% locales Proyecto: Operator-like Assistant local
Metas de la sesión
  • Entender StateGraph, nodos, edges y edges condicionales.
  • Definir un tipo de estado (TypedDict / Pydantic) para tu asistente.
  • Crear nodos planner, executor, reflector que:
    • descomponen la petición del usuario,
    • ejecutan herramientas (o agentes),
    • deciden si la respuesta es suficiente o hay que iterar.
  • Persistir estado en SQLite local, simulando LangGraph + LangSmith pero en tu entorno.
  • Implementar nodos “human-in-the-loop” para acciones críticas.

Checklist Sesión 4

Entregables técnicos
  • langgraph/state.py: definición del estado del asistente.
  • langgraph/nodes.py: implementación de planner, executor, reflector, etc.
  • langgraph/app.py: construcción y ejecución del grafo.
  • Un breve diagrama (puede ser en texto) de cómo fluyen los datos entre nodos.
Esta sesión es clave para pensar en sistemas robustos y reanudables, más allá de simples “chat loops”.

Sesión 5 · Multi-Agente Conversacional (AutoGen-style)

Objetivo: explorar patrones de multi-agente conversacional, donde varios agentes especializados colaboran, se corrigen y generan soluciones complejas usando tu backend local.

Equivalente a: Semana AutoGen Backends configurables (local y/o cloud) Proyecto: Creador de agentes (Agent-Creator local)
Metas de la sesión
  • Configurar un pequeño entorno multi-agente:
    • UserAgent
    • CoderAgent
    • ReviewerAgent
    • PM_Agent (project manager)
  • Definir reglas de quién habla cuándo (speaker selection) y cómo se decide terminar.
  • Diseñar un agente que genere:
    • archivos de configuración,
    • esqueletos de agentes,
    • instrucciones iniciales para nuevos “micro-proyectos”.

Checklist Sesión 5

Entregables técnicos
  • multi_agent/config.py: definición de agentes, roles y parámetros.
  • multi_agent/engine.py: lógica de turnos, selección de hablante, fin de conversación.
  • multi_agent/agent_creator.py: agente que genera código/archivos para nuevos agentes.
Esta sesión te entrena para pensar en sistemas donde varios cerebros IA colaboran, modelo mental clave para proyectos grandes y complejos.

Sesión 6 · MCP-like & Capstone: Trading Floor Local

Objetivo: construir una arquitectura tipo MCP con servicios especializados (precios, noticias, análisis, órdenes) y un Trading Floor multi-agente que funcione completamente en tu PC, con opción a conectar APIs reales en el futuro.

Equivalente a: Semana MCP + Capstone Trading Floor Servicios REST/MCP-like locales Proyecto final: Trading Floor con 4 agentes + N “servers”
Metas de la sesión
  • Diseñar varios servicios independientes:
    • prices_service: datos de mercado (CSV / API simple).
    • news_service: noticias (RSS / archivos locales).
    • analysis_service: indicadores técnicos (RSI, MACD, etc.).
    • orders_service: simulador de órdenes/portfolio.
  • Exponerlos vía HTTP/JSON con contratos claros (MCP-like).
  • Crear agentes:
    • QuantAgent
    • FundamentalAgent
    • PortfolioManager
    • RiskManager
  • Orquestar a los agentes con:
    • tu runtime (Sesión 2), o
    • CrewAI, o
    • LangGraph como grafo orquestador.

Checklist Sesión 6

Entregables técnicos
  • services/prices_service.py, news_service.py, analysis_service.py, orders_service.py.
  • trading_floor/agents.py: definición de agentes financieros.
  • trading_floor/orchestrator.py: lógica que coordina agentes y servicios.
  • Logs CSV/JSON con ejecuciones de sesiones de trading simuladas.
Este capstone es tu “prueba de fuego” agéntica: si puedes construir y entender este sistema, tienes todo lo necesario para proyectos reales con clientes o productos propios.
